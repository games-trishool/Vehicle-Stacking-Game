# Validation

The prepared cloud machine builds and runs the game. Production assets are entirely local.

- `npm run build`: strict TypeScript compilation and Vite production bundling passed.
- `npm test`: all 11 tests passed. Seven cover progression and settings; four use real Cannon ES simulation to check first wheel contact with the platform, contact with the lower ground, safe stacking on the starting vehicle, and a previously supported vehicle sliding onto the platform.
- All 10 browser tests passed together. Browser checks use actual Chromium with software WebGL. They exercise the six live environments, fixed-vehicle selection, saved world and settings, garage purchases and insufficient coins, mobile layouts, music playback, ground-contact losses, and browser errors. Browser title and home branding display the requested name, “Stack Vechiles”; Android launcher/activity labels were also checked in the native resources.
- A first-drop corner miss is performed through normal input. It ends on platform contact with zero score/stacks, no held vehicle, and music stopped. The result buttons have at least a 12px gap and fit 320×480, 480×640, and 390×844 screens; returning home and starting again clears the contact state and old vehicles.
- The audio check measures the actual music signal through a Web Audio analyser, including an averaged level above 0.06 after fade-in. The new 126 BPM arcade score includes drums, bass and a bright melody; its rendered waveform is normalized and its peaks are bounded. Checks cover default playback with effects muted, pause/resume, silence after returning home, a saved music-off preference after reload, and playback after re-enabling it. The physics check also confirms that music remains active through several landings and stops at game over.
- The touch layout test checks 320×480, 320×568, 360×640, 390×844, 412×915, 844×390, and 1366×768 viewports. It checks document and dialog overflow, visible text and control bounds, the live preview, and the main buttons' touch target sizes. At four phone sizes it sends actual touch swipes through the vehicle, place, and garage lists, verifies the last choices are reachable, and checks that headings and the document stay fixed. Choosing Beach at the bottom preserves the scroll position. Achievements and ten leaderboard entries remain reachable through Previous/Next buttons. Settings, help, play, and pause are also exercised.
- The physics browser test performs three centered drops through normal keyboard input, observes points and earned coins, checks pause/resume, then drops off-center to end and save the run. It reads diagnostic positions to time input; it does not alter physics bodies, scores, or simulation time. It uses the space world and a mobile viewport to make the software renderer practical.
- Replay cleanup checks count vehicle models in the actual scene, including any untracked models. After a failed tower, “One more climb” starts with exactly the base and held vehicles, zero score and run coins, and full stability. Separate checks restart and return home through the pause menu while a vehicle is falling, then verify that home contains only its four preview vehicles. The regression was reproduced before the fix: restart left three models instead of two.
- Release AAB: `bundleRelease` passed after a fresh production build and Capacitor sync using Java 21, API 35, and Gradle 8.11.1. `releases/Stack-Vechiles-1.0.1-unsigned.aab` is 4,326,020 bytes. Google bundletool 1.17.1 validation passed; its dumped manifest confirms package `com.trishool.stackline`, version code 2 / version 1.0.1, minimum API 23, target API 35, and no debuggable flag. ZIP integrity and all 29 production web assets were checked. SHA-256 is recorded in `releases/SHA256SUMS.txt`. The shared AAB is unsigned and requires the owner's registered upload-key signature before Play Console upload. Earlier debug-APK checks apply to the previous 1.0 build, not this update.
- The dependency-free local signing helper was checked again with the 1.0.1 bundle using both a newly generated temporary RSA upload key and the same key through its existing-key flow. Both signed test bundles passed independent `jarsigner` verification. The temporary key and signed test bundles were deleted; no production signing key was created or published. The helper now defaults to reusing the previous key if it finds it in its standard location. These checks ran on Linux; Windows-specific JDK discovery has not been executed in this environment.
- Actual WebGL submission measurements across all six worlds show 15.5–27.4% fewer draw calls in the fixed mobile home-preview scenario. Geometry counts and batching/culling tradeoffs are recorded alongside the before/after reports in [PERFORMANCE.md](PERFORMANCE.md). These are rendering-work measurements, not physical-device FPS, thermal, or battery measurements.
- Two new browser tests use a touch viewport with device scale 2.625 and an eight-core device profile. They verify that menus/pauses stop scheduling and rendering WebGL frames after pending work settles, that graphics changes request a redraw without restarting continuous rendering behind the menu, and that closing/resuming restarts the live scene. Auto/High/Battery saver select the expected resolution, shadow, and city-light budgets. A simulated visibility lifecycle pauses a live run, leaves it idle after visibility returns, and resumes only after player input; the physics state and clocks are not modified by the test. Native Android lifecycle and actual Pixel 8 behavior still require the device checklist.
- After the final instance-buffer disposal changes, the six-world/preferences test and the real-physics/perfect-landings/particle-expiration/replay test were repeated against the final production build; both passed. The AAB was rebuilt, revalidated, and both signing flows were checked again against that final artifact.

This verifies builds and browser functionality, not Android device frame rates or Google Play acceptance. Physical-device testing, production signing, current store/API policy review, production art, and an online leaderboard backend remain release work. Rankings in this version are explicitly local.

The saved environment instructions must be reviewed and published in environment settings to create a reusable snapshot. Saving a draft does not publish it, and fresh-task restoration has not been tested.
