# Validation — 1.1.0

The prepared cloud environment builds and runs the game. All production game assets are bundled locally.

- `npm test`: all **14 tests passed**. Seven cover progression, purchases, persistence, and settings; four use real Cannon ES simulation for first platform/ground contact and safe stacking; three cover impact thresholds, collision deduplication/cooldowns, strength scaling, replay reset, and the generated crash waveform at 32/48 kHz. Crash samples are finite, peak-bounded, broadband, and decay into a quiet tail.
- `npm run build`: strict TypeScript compilation and Vite production bundling passed. The final build includes crash-buffer preparation on the first interaction, so waveform generation is avoided during the first impact.
- All **11 browser checks passed across the regression run and targeted rerun** in Chromium with software WebGL. The first full run passed ten checks and exposed an 11px settings-description overflow at 320×480. The copy was shortened. The complete touch-layout check and crash-audio check then both passed against the final production build. Tests were not disabled and assertions were not relaxed.
- The real-physics gameplay check times normal keyboard input for three centered drops, observes points/coins/perfect bonuses, pauses/resumes, misses to end the run, and verifies replay cleanup. Tests do not alter bodies, scores, positions, or simulation time. First platform contact ends a corner miss immediately, and result buttons remain separated. Returning home or restarting while a vehicle is falling removes the old tower.
- Six environments, fixed/mixed selection, saved preferences, garage purchases and insufficient coins, keyboard focus, achievements, and local rankings are exercised. No browser rendering errors were observed in the six-world check.
- Touch layouts cover 320×480, 320×568, 360×640, 390×844, 412×915, 844×390, and 1366×768. The document stays fixed. Real touch gestures reach every vehicle, place, and garage item while dialog headers remain fixed. Settings/help/pause fit; achievements and rankings remain reachable through their page controls.
- The crash-audio browser check drops a vehicle through normal input, observes a physical contact above the noise threshold, a crash playback event, and a nonzero Web Audio analyser signal. It then disables Sound effects, reloads, repeats the real collision, and confirms zero crash playbacks and silent effects output. Music remains independently configurable. This verifies the audio graph, not how a particular phone speaker sounds.
- Background-music checks cover default playback with effects muted, audible output after fade-in, pause/resume, silence on home/game over, the saved music-off preference, and re-enabling music. The original 126 BPM soundtrack is rendered once, normalized, and peak-bounded.
- Rendering/lifecycle browser checks use a touch viewport, device scale 2.625, and an eight-core profile. Menus and pauses stop scheduling/rendering after pending work settles; graphics changes request a redraw; closing/resuming restarts animation. Auto/High/Battery saver select the expected pixel ratio, shadow, and city-light budgets. Simulated visibility events pause the run and require player input to resume. Native lifecycle behavior still needs a physical Android check.
- All six redesigned models were visually reviewed in a neutral-lit gallery and in the live game/garage. They use original generated geometry, reflective PBR materials, and a shared procedural tire texture. Each model uses 8–9 material batches and approximately 16,500–18,500 triangles. Raw model counts and current six-world rendering measurements accompany [PERFORMANCE.md](PERFORMANCE.md). Increased geometry and clearcoat shading require device profiling; unchanged draw-call counts do not guarantee unchanged FPS.
- The final Android `bundleRelease` build passed with Java 21, API 35, and Gradle 8.11.1 after a fresh production build and Capacitor sync. `Stack-Vechiles-1.1.0-unsigned.aab` is **4,323,586 bytes**. Google bundletool 1.17.1 validation passed. Its dumped manifest confirms package `com.trishool.stackline`, version code **3**, version **1.1.0**, minimum API 23, target API 35, and no debuggable flag. ZIP integrity and byte equality of all **29 production web assets** were checked. SHA-256 is recorded in `releases/SHA256SUMS.txt`.
- The local signing helper was exercised against that final bundle with a newly generated temporary RSA upload key, then the same key through the existing-key flow. Both outputs passed independent `jarsigner` verification. The temporary key and signed test files were deleted. No production upload key was created or published. The shared bundle remains unsigned and must be signed locally using the owner's registered upload key. These checks ran on Linux; Windows-specific JDK discovery was not executed here.

These checks verify builds and browser functionality. Physical Pixel 8 frame times, thermals, audio balance, vibration, Android WebView/lifecycle behavior, and current Google Play requirements remain device/store checks. Rankings remain local. Follow the [Pixel 8 checklist](PERFORMANCE.md#pixel-8-checks-before-the-next-release) before rolling out the update.
